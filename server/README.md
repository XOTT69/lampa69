# XOTT TV API: Cloudflare Workers + D1 + Telegram

Сервер забезпечує вхід на телевізорі через одноразовий код, підтвердження в особистому Telegram-боті, сесії, закладки та прогрес. Публічний GitHub Pages самостійно ці функції виконати не може.

## Одноразове підключення інфраструктури

Потрібні власний Cloudflare-акаунт та окремий бот від @BotFather. Не використовуйте токен іншого робочого бота: зміна webhook відключить його поточний сервер.

1. У каталозі `server/`: `npx wrangler@4 login`.
2. `npx wrangler@4 d1 create xott-tv-db`.
3. Вставити отриманий `database_id` у `wrangler.jsonc`; встановити `BOT_USERNAME` без `@`. `APP_ORIGIN` — походження сайту без шляху; початково `https://xott69.github.io`.
4. `npx wrangler@4 d1 migrations apply xott-tv-db --remote`.
5. `npx wrangler@4 secret put BOT_TOKEN` — токен свого нового бота.
6. Створити випадковий webhook-секрет (наприклад `openssl rand -hex 32`) та додати через `npx wrangler@4 secret put TELEGRAM_WEBHOOK_SECRET`.
7. `npx wrangler@4 deploy`. Зберегти HTTPS-адресу Worker.
8. Локально задати `BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `API_URL` у змінних оточення й виконати `node setup.mjs`. Скрипт встановлює webhook і меню команд. Секрети не передавати в URL браузера або GitHub.
9. У GitHub → Settings → Secrets and variables → Actions → **Variables** додати `XOTT_API_URL` з адресою Worker. Це публічна адреса, не секрет. Перезапустити workflow збірки сайту.
10. Увімкнути GitHub Pages із джерелом **GitHub Actions**, якщо ще вимкнено.

## Власний каталог джерел

За бажанням встановити `CATALOG_URL` у `wrangler.jsonc` на доступний серверу HTTPS JSON із форматом `../catalog.example.json` та повторити deploy. Плагін отримує потоки через `/api/sources` тільки після входу. Сервер не є відкритим довільним проксі: адресу каталогу задає власник, запити користувача не можуть змінити серверний URL.

Можна також використовувати публічний каталог без сервера: GitHub Variable `XOTT_CATALOG_URL` або URL у налаштуваннях XOTT Sources. У такому каталозі не можна розміщувати приватні ключі. API повертає прямі MP4/HLS/WebM; HTML-плеєри та iframe відхиляються. Потоки не транскодуються: кодеки й доступність перевіряються на пристрої.

`tmdb_id` + `type` точно пов'язують фільм/серіал з карткою. Кожен `stream` може мати `season`, `episode`, `voice`, `language`, `quality`, `name`, `url`. Реклама всередині готового відеофайла або серверного HLS-потоку не визначається й автоматично не вирізається.

## Безпека й поведінка

- Код із 8 символів діє 10 хв; для polling потрібен окремий випадковий секрет, якого немає в Telegram-посиланні.
- Після надсилання коду потрібне окреме підтвердження кнопкою в Telegram. Інший Telegram-користувач підтвердити його не може.
- Webhook захищений `X-Telegram-Bot-Api-Secret-Token`. Токен бота зберігається тільки в Worker secrets.
- Сесії діють 90 днів. У D1 зберігається SHA-256 токена, а не відкритий токен.
- `/logoutall` у боті відкликає всі сесії та незавершені входи користувача.
- Сервер приймає тільки `favorite` і `file_view`; плагіни, паролі та налаштування Filmix не синхронізуються.
- Зміни стану захищені номером версії; застарілий запис отримує HTTP 409. Клієнт повторює синхронізацію після перечитування даних.
- Локальні бібліотеки різних Telegram-акаунтів розділяються за непрозорим ID, а не іменем. При зміні акаунта попередня бібліотека лишається локально як окрема копія.
- Є ліміти запитів, обмеження розміру JSON і планове видалення прострочених входів/сесій. Логування запитів вимкнене.

## Перевірки

Із кореня репозиторію: `npm run test:server` (Node 22+). Інтеграційні тести використовують справжню SQLite та підміняють лише мережевий Telegram API. Вони перевіряють код → повідомлення боту → підтвердження → сесію, повторне використання, іншу особу, прострочення, вихід, приватність даних, конфлікти версій і перевірку потоків.

Ці тести не замінюють живий deploy з власними секретами і запуск на Hisense. Без додавання `BOT_TOKEN`, webhook-секрета, D1 та адреси API реальний Telegram-вхід не активний.

## Адаптери джерел 2.1

`providers.mjs` працює без токенів і має фіксовані маршрути:

- `GET /api/providers` — список адаптерів і умови доступу.
- `GET /api/providers/filmix/search?query=...` — пошук.
- `POST /api/providers/filmix/streams` з `{"id":"..."}` — гостьові потоки до 480p.
- `GET /api/providers/rezka/search?query=...` — експериментальний пошук HDRezka.
- `POST /api/providers/rezka/details` і `/streams` — гостьові фільми; серіали в UI цього адаптера не ввімкнені.

`worker.mjs` уже маршрутизує ці запити та застосовує CORS і ліміт запитів. Після Worker deploy вказати `XOTT_PROVIDER_API_URL=https://worker/api/providers` у GitHub Variables або налаштуваннях плагіна.

Обмежені правовласником посилання, очевидні рекламні URL та преміальні відповіді не відкриваються. Переадресації й перевірки браузера повертаються як помилка джерела. Адаптер не є довільним проксі й не приймає адреси сторонніх серверів від клієнта. Доступність пошуку не означає доступність потоку для кожного фільму.

AniLiberty: `GET /api/providers/aniliberty/search?query=...` та `POST /api/providers/aniliberty/streams` з ID релізу. Використовуються лише параметри джерела для вимкнення відеореклами; `isAuthorized` та інші параметри доступу не змінюються. Перший HLS-плейлист перевіряється на явні рекламні мітки, відмова джерела не запускає рекламний fallback. Нумерація серій — абсолютна. Перевірка плейлиста не доводить відсутності реклами, вшитої у відеоряд.
